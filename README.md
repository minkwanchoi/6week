# 주간보고 자동 작성 실습

줄글로 적은 업무 메모를 주간보고 형식으로 바꾸는 일을 AI 에이전트(Claude Code)에게 맡겨 본 실습 기록입니다. 손으로 10분 걸리던 작성을 3분 이내로 줄이는 것이 목표입니다.

이 저장소의 업무 내용·이름·기관·장소·일정은 모두 실습용으로 지어낸 예시입니다.

## 하는 일

- 입력: `raw/`의 업무 메모와 이전 주간보고
- 결과: `out/`의 주간보고 한 파일(금주 업무 기한 표 → 금주 업무 → 차주 업무)
- 같은 과제의 업무는 한 항목으로 묶고 그 안에서 업무별 소절(1-1, 1-2)로 나눕니다.
- 메모에 없는 개요·내용은 이전 주간보고를 토대로 제안하고 끝에 `[제안함]`을 답니다.
- 기한·일시·장소·참석자 같은 사실 항목은 지어내지 않고 `〔확인 필요〕`로 남깁니다.
- 메모에 참조 URL이 있으면 실제로 열리는지 확인합니다.

자세한 규칙은 [CLAUDE.md](CLAUDE.md)에 있습니다.

- [주간보고_예시.md](raw/주간보고_예시.md): 옛 구조(업무마다 한 항목), 형식의 기준으로 쓰지 않음

### out/

- [주간보고_10-12_10-16.md](out/주간보고_10-12_10-16.md): 옛 구조로 만든 첫 결과
- [주간보고_10-19_10-23.md](out/주간보고_10-19_10-23.md): 줄글 메모로 만든 결과(과제별 소절 구조)

- [판-가_결과_URL.md](out/판-가_결과_URL.md), [판-나_결과_URL.md](out/판-나_결과_URL.md): URL이 있는 메모에 두 판의 규칙을 각각 적용한 결과

## 규칙 두 판의 비교

참조 URL을 다루는 규칙 한 줄만 다르게 두고 같은 메모로 결과를 비교했습니다.

| 판 | 규칙 한 줄 | 틀린 주소 3건의 처리 |
| --- | --- | --- |
| 판-가 | 입력: 참조 정보 URL | 메모에 적힌 그대로 보고에 실음 |
| 판-나 | 검증: 참조 정보 URL의 유효성 검증 | 3건 모두 `〔확인 필요〕`와 사유를 붙임 |

틀린 링크가 보고에 들어가는 것을 막을 수 있어 판-나를 골랐습니다. 경과는 [5주차_기록.md](5주차_기록.md)에 있습니다.

## 저장소에 넣지 않는 것

실제 자료가 올라가지 않도록 [.gitignore](.gitignore)로 다음을 뺍니다.

- `raw/`의 파일(이름이 `_예시.md`로 끝나는 예시만 넣음)
- `out/`에 새로 생기는 결과물(지어낸 값으로 만든 예시만 골라 넣음)
- 한글·오피스 문서, 표 파일, 그림 파일, PDF
- 환경 설정 파일, 인증서와 개인 키
